# AGENTS.md

## Описание проекта

React-приложение, демонстрирующее имплементацию VIPER архитектуры на основе принципов Роберта Мартина из «The Clean Architecture».

**Стек:** React 19, TypeScript, Zustand, CSS Modules, Vite, yarn

## Архитектура

### VIPER модули

| Понятие | Описание |
| ------- | -------- |
| **View** | JSX-компонент без логики |
| **Interactor** | tasks = бизнес-логика приложения. Не зависит от выбора фреймворка для View или state manager-а для Entity |
| **Presenter** | hook `usePresenter`. Логика компонента: подготовка данных, обработка событий. Не содержит бизнес-логику |
| **Entity** | Zustand store. Хранилище данных. Не содержит бизнес-логику |
| **Router** (wip) | Глобальные переходы между страницами |

*wip = work in progress. Эту часть ещё не реализовали.

### Структура директорий

```
src/

│   └── ComponentName/                  # Пример компонента без логики. Название компонента = ComponentName
│   │   ├── index.tsx                   # View, IProps
│   │   └── component-name.module.css   # Стили
│   │
│   └── ComponentName/                  # Пример компонента с логикой. Название компонента = ComponentName
│       ├── index.tsx                   # View
│       └── logic                       # Логика компонента
│       │   └── usePresenter.tsx        # Presenter
│       ├── types.ts                    # IProps и другие интерфейсы, которые использует только этот компонент
│       └── component-name.module.css   # Стили
│
│
├── pages/                              # Компоненты страниц
│   └── PageName/                       # Пример крупноблочного компонента приложения - страницы. Название компонента = PageName
│       │                               # Правила оформления аналогичны компоненту из UI Kit-а
│       ├── index.tsx                   # View
│       └── logic                       # Логика компонента
│       │   └── usePresenter.tsx        # Presenter
│       ├── types.ts                    # IProps и другие интерфейсы, которые использует только этот компонент
│       ├── page-name.module.css        # Стили
│       ├── components/                 # Переиспользуемые компоненты, которые используются в нескольких дочерних компонентах
│       └── ChildComponent/             # Дочерний компонент PageName. Используется только в PageName
│                                       # Правила оформления аналогичны компоненту из UI Kit-а
│                                       # Может содержать сколько угодно уровней вложенных компонентов
│                                       # Может содержать папку components/
│
│
├── store/                              # Zustand stores (Entities)
│   └── someStore.ts                    # Пример Zustand store. Название сущности = some
│
│
├── tasks/                              # Interactor, бизнес-логика
│
│
├── hooks/               # Общие хуки
├── utils/               # Общие утилиты
└── types/               # Общие типы
```

## Алгоритм создания нового компонента

### 1. Определяем место расположения компонента

Все компоненты для UI-kit уходят в папку `src/components`.
Сюда односятся компоненты, которые не зависят от контекста их вызова.
Они ничего не знают про страницу, на которой их вызвали.
Хорошие примеры: Button, Input, Pagination.
Неправильный пример: ShowsFilter. Этот компонент относится к старице списка тв-шоу. Он может существовать только в контексте этой страницы.

Остальные компоненты создаются внутри `src/pages`. Компонент должен быть непосредвенный ребёнком того компонента, где он используется. Может быть сколько угодно уровней вложенности.

### 2. Определяем тип компонента

У нас есть 2 типа компонентов:
- `view`,
- `presenter`.

`view` - это простейший компонент без логики. Он только отображает данные. Никаких hook-ов он вызывать не может.

`presenter` - это компонент с какой-либо логикой.

### 3. Создаём компонент по шаблону

Вызываем команду `yarn generate <view/presenter> <название компонента> <директория относительно src>`.

Пример удачной команды для создания уже существующего компонента ShowCard:
`yarn generate view show-card pages/ShowListPage`.
